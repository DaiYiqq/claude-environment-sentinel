# 防封指南：把“环境一致性”放回风险模型里

> 这是一份**风险认知文档**，不是“操作秘籍”。Anthropic 没有公开完整的账号风控评分规则；下面描述的是这类服务常见的风险维度，以及 Sentinel 能/不能影响的部分。不要把任何本地工具当作账号结果的承诺。

---

## 0. 先说明三件事

1. **服务端风控是持续运行的评分体系。** 登录、请求频率、IP 质量、支付、设备、行为等信号会被综合评估，而不是只看“时区对不对”。
2. **本地环境对齐只能减少“内部矛盾”信号。** 它更像是让资料自洽，不是加分项，更不是“绕过检测”。
3. **IP 质量优先于本地伪装。** 如果出口 IP 已经被大量账号共用、在黑名单里，或者本身就是机房/代理池，时区和语言调得再整齐也无法把它变干净。

Sentinel 的存在意义是：把“本地环境画像和网络出口地区冲突”这一类容易自查、可回滚的问题自动化，并给你一个能在异常时切断网络的开关。它不处理服务端对账号本身的判断。

---

## 1. 风控是多维评分，不是单一开关

常见的评估维度包括：

- **注册/早期信号**：注册 IP 的地区与质量、邮箱类型、支付方式、初始设备环境。
- **网络信号**：出口 IP 的 ASN 类型（住宅/移动/机房/代理）、是否被标记为 VPN/Tor、IP 是否频繁变化、DNS 出口是否与流量出口一致。
- **环境一致性**：系统时区、系统语言、浏览器 `Accept-Language`、Node/Electron 可见 locale、WebRTC 暴露的地址是否与出口地区自洽。
- **行为信号**：请求频率、并发、限额消耗速度、是否频繁退出重登、是否在短时间内跨地区跳变。
- **账号历史**：账号年龄、历史是否稳定、是否出现过争议/退款/滥用报告。

这些维度通常不是简单相加，而是分层、带权、可能随时间衰减的。Anthropic 没有公开具体公式，所以任何“做到 X 就没事”的说法都不可信。

**Sentinel 能影响的**：系统时区、用户级语言、浏览器语言/WebRTC 策略、出口地区一致性、异常时的断网。
**Sentinel 不能影响的**：IP 的历史信誉、账号历史、支付风险、服务端行为模型、地区可用性政策。

本地环境对齐的价值是“**不减分**”：当其他信号已经不利时，至少不要让本地画像再制造明显矛盾。它不是“加分”，也不是“消除风险”。

---

## 2. IP 质量优先于本地伪装

这是最重要的一条。

### 2.1 为什么 IP 质量优先

- 一个被大量账号共用的机房 IP，即使每个账号都把时区/语言调得完美，仍然共享同一个“坏邻居”风险。
- 代理/VPN/Tor 出口在商业风控里通常是高风险类别；住宅 IP 也不等于“干净”，还要看历史行为。
- 频繁更换出口 IP 本身就会形成“不稳定”信号；今天日本、明天德国、后天美国，比固定一个地区更容易被注意到。

### 2.2 Sentinel 如何呈现

- A5：出口国家/地区；
- A6：ASN 与 IP 类型（住宅/移动/机房/代理/Tor）；
- A7：与上次审计相比 IP/国家是否变化；
- A13：DNS 出口是否与主出口一致；
- A8/A9：本地时区/语言是否与出口地区自洽。

Sentinel 会把机房 IP 标为警告，把代理/Tor 标记标为失败，把换国标为失败。它**不能**把 IP 从黑名单里移除，也不能把共享 IP 变成独享住宅 IP。

### 2.3 务实建议

- 优先选择**稳定、干净、与你账号地区一致**的出口，而不是频繁轮换。
- 不要用同一个出口同时跑大量账号；不要把“能连上”误认为“质量好”。
- 如果你无法判断 IP 质量，至少保持**长期稳定**，不要今天换一个国家、明天换另一个。
- 不要用 Sentinel 的“审计通过”来推断 IP 干净。审计通过只表示“Sentinel 能检查的本地项没有发现硬冲突”。

## 3. 一致性比“正确”更重要

### 3.1 什么叫一致

系统时区、系统语言、浏览器 `Accept-Language`、Node/Electron 看到的环境、出口 IP 地理位置，应该讲同一个故事。

例如：

- 出口 IP 在美国西海岸，系统时区却是东八区；
- 系统是中文，浏览器却只发 `en-US`；
- 浏览器走代理，Claude CLI 却直连；
- DNS 从另一个国家出去；

这些都会制造“内部矛盾”。矛盾不一定导致处理，但它是你可以主动减少的一类信号。

### 3.2 为什么“频繁跳变”比“不完美”更糟

一个长期稳定在某个地区、环境略有瑕疵的账号，通常比一个每天跨三大洲跳变的账号更容易解释。**稳定性本身就是信号。**

Sentinel 的 A7（IP 变化）和 A20（配置漂移）就是在提示这一点。A20 不直接阻断启动，但它提醒你：关键配置在短时间内变了很多次。

### 3.3 用历史看“稳定性”，而不是用单次分数求安心

Sentinel 的审计历史和趋势图用于观察一个更现实的问题：**过去一段时间里，环境是否在频繁变化？**

- 风险分突然上升，往往比某个单点警告更值得停下来看；
- 出口国家/时区在短时间内反复变化，是明显的不稳定信号；
- 国家锁定可以让安全启动在出口偏离预期时直接失败，而不是“先启动再说”；
- 历史记录只保存摘要，不保存凭证或账号材料。

不要把一次低风险分当成“安全证明”。它只表示这一次本地采样没有发现硬冲突。

### 3.4 一键对齐能做什么、不能做什么

浏览器控制台和桌面版都可以执行一键对齐/还原：

- 能改：用户级 `TZ/LANG/LC_ALL`，可选系统时区，Chrome/Edge 语言与 WebRTC 策略；
- 能还原：按快照逐项写回，原本不存在的变量会删除；
- 不能改：出口 IP、代理线路质量、账号历史、服务端风控、你的操作行为。

对齐只让本地环境更自洽，不会把机房 IP 变成住宅 IP，也不会让一个新号变成老号。
因此它是“减少可避免的本地冲突”，不是对封号概率数值的承诺。

### 3.5 一致性的优先级

1. 出口 IP 与账号注册/使用地区一致；
2. 系统时区与出口时区在合理偏移内（A8，±2 小时容差）；
3. 系统语言与出口地区不出现硬冲突（A9）；
4. 浏览器 `Accept-Language` 与出口地区一致（A16）；
5. WebRTC 不暴露非出口公网地址（A14/A17）；
6. 字体、DNS 等较弱信号（A15/A13）作为提示。

不要为了追求“完美”而频繁修改环境；**稳定地一致**比“每次都很正确但每次都不同”更有意义。

## 4. 行为模式同样被评分

环境只是其中一层。以下行为在多数商业风控中都属于高关注信号：

- 短时间内耗尽限额；
- 持续高并发、批量请求；
- 短时间内频繁切换 IP/地区；
- 反复退出登录、重新登录、切换账号；
- 新账号立刻大额订阅或高频使用；
- 多个账号共享完全相同的设备/浏览器环境；
- 使用明显自动化的节奏访问。

### 4.1 稳定使用的建议

- 给账号一个相对固定的地区和使用节奏；
- 避免短时间内的限额冲刺；
- 不要频繁退出/重登来“刷新”状态；
- 多账号场景下，不要在同一分钟里来回切换环境；
- 如果你必须切换环境，切换后先稳定一段时间，再进行高强度操作；
- 保留自己的正常使用模式，不要为了“像真人”而制造另一种异常。

### 4.2 Sentinel 能做什么

- 在安全启动后监控出口国家/IP、代理内核、TUN；异常时终止 Claude 并阻断重连。
- 让你在切换环境前先做一次完整审计。
- 记录触发原因和原始采样，方便你复盘。

### 4.3 Sentinel 不能做什么

- 不能判断服务端的行为评分；
- 不能替你决定请求频率；
- 不能阻止你在多个账号之间快速切换；
- 不能把“高频/批量”行为变得安全。

---

## 5. 新号与老号的容错空间不同

### 5.1 新号

新号通常缺少历史信用，任何异常信号的影响都更明显。建议：

- 注册后先稳定环境和使用地区；
- 不要在第一天就大额订阅、短时间耗尽限额或高频并发；
- 不要在多个地区之间跳变；
- 不要频繁退出重登；
- 不要在同一台机器上同时维护大量新号；
- 先观察账号是否稳定，再逐步增加使用强度。

### 5.2 老号

老号有历史行为作为缓冲，但这不是“免疫”。建议：

- 保持原有地区/环境习惯，不要突然大改；
- 如果必须迁移地区，分阶段、低速进行；
- 不要因为“老号”就忽略明显的环境冲突；
- 定期检查是否有配置漂移（A20）。

### 5.3 共同原则

- **稳定 > 完美**；
- **少变 > 多变**；
- **质量 > 数量**；
- **本地一致 > 单点伪装**。

## 6. 法律、条款与边界

### 6.1 这不是“绕过地区限制”的工具

Sentinel 的目标是降低本地环境画像冲突造成的**误判风险**，不是帮助规避地区服务限制。Anthropic 的服务条款、使用政策和地区可用性政策是独立于本地环境的另一层约束。

- 如果你的地区不支持相关服务，正确做法是遵守政策，而不是用本地工具伪装；
- 不要用 Sentinel 规避支付、身份、地区或其他合规要求；
- 不要用它批量注册、共享账号或从事违反条款的行为。

### 6.2 官方信息

请以 Anthropic 官方页面为准：

- 消费者条款：<https://www.anthropic.com/legal/consumer-terms>
- 使用政策：<https://www.anthropic.com/legal/aup>
- 支持的国家/地区：<https://www.anthropic.com/supported-countries>
- 隐私政策：<https://privacy.anthropic.com/>

这些页面可能更新；Sentinel 不复制、不解释、也不替代它们。你所在地区的法律和平台条款优先于本指南。

### 6.3 数据与隐私

Sentinel 不读取 Claude 登录态、Cookie、Token、会话文件或浏览器账号资料。它只读取环境变量、系统时区、浏览器语言/WebRTC 策略、网络元数据和客户端程序版本。所有报告和日志都在本地。

多环境配置包只保存“环境配置”，不保存“身份材料”。切换账号需要你在 Claude 内自行完成登录切换；Sentinel 不代劳，也不接触凭证。

## 7. 一张可执行的检查表

每次准备长期使用前，按顺序确认：

- [ ] 出口 IP 的地区是我期望的，并且近期稳定；
- [ ] A6 没有代理/Tor 标记；机房 IP 已了解其风险；
- [ ] A8 的时区偏移差在 ±2 小时内；
- [ ] A9 没有中文系统 + 欧美 IP 这类硬冲突；
- [ ] A10/A11 代理变量与代理内核一致，没有“配置了但没运行”；
- [ ] A12 我清楚当前是 TUN、系统代理还是直连；
- [ ] A13 DNS 没有明显泄漏；
- [ ] A14/A17 WebRTC 策略合理；
- [ ] A16 浏览器语言与出口地区一致；
- [ ] A19 系统时钟偏差正常；
- [ ] 最近没有频繁切换地区/账号；
- [ ] 我的使用节奏没有短时冲刺/高频并发。

如果以上大部分不满足，先不要启动，更不要用“多开”“换 IP”“反复重登”来试图解决。**停下来，先把一致性做好。**

---

## 8. Sentinel 不做什么

- 不伪造设备指纹；
- 不修改 Claude 客户端或浏览器可执行文件；
- 不处理登录凭证、Cookie、Token、会话文件；
- 不修改 Hosts、内核参数、驱动；
- 不承诺账号结果；
- 不绕过服务端风控；
- 不替你做“是否违反条款”的判断。

它只做三件事：**审计、可回滚对齐、异常时断网**。把这三件事做好，剩下的仍然取决于 IP 质量、账号历史、行为模式和平台政策。

---

## 9. 结语

“防封”这个词容易让人误以为存在一个开关。现实更像是一组持续变化的信号：IP 质量、环境一致性、行为节奏、账号历史。Sentinel 能帮你把其中“本地环境不一致”这一层做得更干净、更可回滚，但它不能替你控制其余变量，也不承诺结果。

如果你只能记住一句话：

> **稳定、干净、一致的网络与行为，比任何本地伪装都更重要。**
